# Split provenance

Regenerated 2026-09-21 after fixing the seed-derivation defect in `src/data/split.py`.

## Why the split changed

The per-group RNG seed was derived from `abs(hash(str(species)))`. Python salts `str`
hashing per process unless `PYTHONHASHSEED` is set, which it is not anywhere in this
repository. Three consecutive runs of the archived `split.py` at `seed: 1337` produced
three different splits:

```
val b27a3aa60467e300  test 7c25d9ad62408fe2
val 22b35d5e277f3714  test 48389c27180ad7af
val 861cd0e3534068ba  test 894b0ec30affca19
```

`hash()` was replaced by `stable_hash()`, a SHA-256 digest truncated to 64 bits. Three
consecutive runs now produce byte-identical output, so the split is regenerable from the
seed alone.

## Relationship to the submitted split

This is a genuinely different partition, not a reordering: only 20 of 202 val images and
11 of 202 test images are shared with the archived split
(`04_ARCHIVE/pre_revision_v2_snapshot_20260921/processed/manifest/splits/`). Every
accuracy figure in the submitted manuscript therefore refers to the archived split and
cannot be compared directly against results computed here.

## Denominator note

`views_resized.csv` holds 8,219 images, but the splits total 5,967. The difference of
2,252 images is z-stack slices dropped by `_subsample_z_slices`, which caps val and test
at 5 slices per view and **discards** the surplus rather than returning it to train. The
modelling denominator is therefore 5,967, not 8,219, and manuscript text must name which
number it means.
